# Книга случаев

Требование владельца 13.10.2026: «чтобы не повторялись ошибки и не ходить
кругами»; «не только жалоб, а и предложений ввести новое — чтоб новое не
ломало старое». Поэтому **каждая жалоба и каждая введённая возможность —
случай в книге**, и перед любой выкладкой вся книга должна быть зелёной.

## Как это работает

| Что | Где | Когда |
|---|---|---|
| Случаи | `kniga/cases/NNN-имя.json` | один файл — один случай |
| Сохранённые страницы сайтов | `kniga/slices/<срез>.zip` + `.json` | нарезаны из сбора |
| Прогон книги | `python scripts/kniga.py` | ~1 мин |
| Всё перед выкладкой | `python scripts/proverka.py` | тесты + книга, ~3 мин |
| То же + старый/новый код на последнем сборе | GitHub, `proverka.yml` | на каждый push кода |
| Шлагбаум в main | `scripts/push_gate.py` (git `pre-push`) | push в main |

Итог владельцу — одна строка: `книга: 44 случаев, все зелёные`.

## Порядок выкладки

1. Ветка от main, правка, **случай в книгу** (новый или поправленный).
2. `python scripts/proverka.py` — зелёный.
3. Влить в ветку свежий main → `git push` ВЕТКИ → на GitHub «Проверка
   перед выкладкой» (~15–25 мин).
4. Зелёная → слияние в main → `git push`. Шлагбаум сам проверит, что
   GitHub прогнал именно этот код (после проверки — только коммиты сбора и
   сервера в их файлах); иначе не пустит и скажет, что делать.
5. Красная → чинить, не выкладывать. `--no-verify` — только по слову владельца.

Шлагбаум включается один раз на репозиторий (путь — абсолютный, чтобы его
видели и рабочие копии старых веток):
`git config core.hooksPath "<папка движка>/scripts/hooks"` и
`git config streams.python "<путь к python.exe окружения проекта>"`.

## Как добавить случай

**Жалоба на витрину** («игры нет», «не тот канал», «запись вместо эфира»):

1. Сразу, пока архив сбора жив (на GitHub он хранится **3 дня**):
   `python scripts/github_run.py fetch --run N --out <папка>`.
2. Срез — только нужные сайты и дни (эталон flashscore всех языков за эти
   дни идёт в срез сам):
   `python scripts/kniga.py --cut <папка> --name sbor-N-коротко --domains сайт1,сайт2 --days 2026-10-13 --clock "<games.json → собрано>" --what "сбор #N, дата"`.
3. Файл случая (образец — `001-polsha-belgiya-tvp.json`), в «ждём» — что
   ДОЛЖНО быть по словам владельца, а не что выдаёт код сейчас.
4. Проверить, что случай **красный на старом коде** и зелёный на новом —
   иначе он ничего не охраняет.

**Новая возможность или решение владельца** — случай с `"проверка": "тест"`
и списком тестов, которые её проверяют (новый тест — обязательно). Тест без
случая в книге `proverka.py` считает красным.

## Поля случая

| Поле | Что писать |
|---|---|
| `номер` | следующий свободный, не менять |
| `дата`, `вид` | дата жалобы; жалоба / новое / решение / вопрос / находка / слово |
| `суть` | одна строка простыми словами — её видит владелец |
| `владелец` | что он увидел или попросил (по возможности его словами) |
| `правило` | что сделано в коде, коротко |
| `коммит` | слияние в main, которым сделано |
| `проверка` | `разбор` / `ссылка` / `тест` |

Ожидания `разбор` (срез обязателен):

- `{"игра": "Дом - Гости", "время": "ГГГГ-ММ-ДД ЧЧ:ММ", "канал": "…", "сайт": "…"}` —
  игра есть (пара сравнивается как в разборе, пол W и возраст U19 обязаны
  совпасть), начало ±10 мин, у неё есть этот канал от этого сайта;
- `{"снято": "Дом - Гости", "время": …, "сайт": …}` — строку сайта сняли
  фильтром (повтор, запись);
- `{"нет": "Дом - Гости", "время": …, "сайт": …}` — на витрине такой игры
  нет (±3 ч); с `сайт` — нет канала этого сайта у неё.

Ожидания `ссылка` — кнопка ↗: `сайт`, `канал`, `время`, `пояс`,
`адрес_отметки`, `адрес_источника`, `часы_utc` → ровно `ссылка`.

## Потери на последнем сборе

`proverka.py --sravnit` разбирает последний сбор старым и новым кодом.
Пропал канал у игры (пропала игра — значит, все её каналы) — красный,
**если не объяснено книгой**: задуманное снятие сперва записывается случаем
на сохранённых страницах с `нет` или `снято` (та же пара ±3 ч, тот же сайт;
сайт обязан быть в срезе) — по каждому сайту. Так снятие не бывает
случайным. Не потеря: переименование (та же пара или все каналы при новой
записи), двойня, склеенная в прежнюю игру, сдвиг времени до 3 ч — только
если ближе к эталону flashscore (иначе это ошибка пояса).

## Жёлтый

Сорвался только замер скорости (в имени проверки `скорость:`): время
зависит от машины. Пишется в итог, выкладку не держит. Повторяется —
разбираться, что замедлилось.
